# Intranet Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Subir a intranet numa máquina da rede, com Authentik, patrimônio, wiki e chamados atrás de um nginx, no repositório atual.

**Architecture:** Um Compose publica só o nginx (portas 80 e 8081). Postgres fica na rede interna. Cada sistema nosso é dono do seu prefixo. O Authentik é a fonte dos grupos. O patrimônio conserva o modo SQLite do `install.sh` e ganha Postgres quando `DATABASE_URL` existe.

**Tech Stack:** Docker Compose, nginx 1.28, Postgres 16, Authentik `ghcr.io/goauthentik/server:2025.12`, Wiki.js `requarks/wiki` com tag 2.5 fixa, Bun, React 19, Vite.

**Spec:** `docs/intranet.md`

## Global Constraints

- HTTP, IP, sem DNS e sem TLS.
- Prefixo encaminhado inteiro. Nginx não corta `/patrimonio`, `/chamados` nem `/authentik/`.
- `AUTHENTIK_WEB__PATH=/authentik/`. Imagem do Authentik `>= 2025.12`.
- Wiki só em `http://IP:8081/`.
- Cookie dos nossos sistemas: `httpOnly`, `SameSite=Lax`, `Path` do prefixo, validade 900 segundos, grupos efetivos.
- Setor lê. Editor é `setor-*-editores`. Tabela de pais em `docs/intranet.md`.
- Token com `user.all_groups()`.
- `reset_password: true` em senha definida pelo administrador.
- Postgres sem porta publicada. Cinco dumps em `deploy/backups/`.
- Tag de imagem fixa. Segredo só em `deploy/.env`.
- Migração de banco já aplicada não é editada.
- Textos de interface em português.
- `REPO_URL` segue `github.com/gustavogpassos/patrimonio` até o rename.

## Review Focus

- Pessoa do almoxarifado abre `financeiro/fechamento` na wiki e não vê a página.
- Cookie `patrimonio_session` não aparece num request para `/chamados/` nem para a porta 8081.
- Senha temporária com `reset_password` não cria cookie de patrimônio.
- `import-sqlite` com equipamento já no Postgres sai com erro e não escreve linha.
- `update.sh` com migração falha deixa o `.env` e o volume, e imprime o caminho do dump.

### Task 6: Sessão OIDC do patrimônio

**Files:**
- Create: `apps/patrimonio/src/server/session.ts`, `apps/patrimonio/src/server/session.test.ts`
- Modify: `apps/patrimonio/src/server/index.ts`
- Test: `apps/patrimonio/src/server/session.test.ts`

**Interfaces:**
- Consumes: `BASE_PATH`, grupos efetivos no claim `groups`
- Produces:
  - `seal(groups: string[], sub: string, email: string, now: number): string`
  - `open(token: string, now: number): { groups: string[], sub: string, email: string } | null`
  - `hasGroup(groups: string[], name: string): boolean`
  - rotas `GET /patrimonio/api/auth/login`, `GET /patrimonio/api/auth/callback`, `POST /patrimonio/api/auth/logout`

`seal` cifra com AES-256-GCM. A chave é `SESSION_SECRET` em base64, 32 bytes. O payload é `{ groups, sub, email, exp }`. `exp` é `now + 900`. `open` devolve `null` se a cifra falha ou se `now >= exp`.

`hasGroup("patrimonio-baixa")` sem `"patrimonio"` na lista devolve false. `hasGroup` de `"patrimonio"` devolve true.

Toda rota de API, fora de `/patrimonio/api/auth/*`, exige cookie `patrimonio_session` válido e o grupo `patrimonio`. Sem isso, 401.

`login` redireciona ao Authentik e guarda o caminho original (o que veio depois de `/patrimonio`) num cookie `patrimonio_next`, `Path=/patrimonio`, validade curta. `callback` grava `patrimonio_session` e redireciona para esse caminho, ou para `/patrimonio/` se o cookie não existir. `logout` apaga `patrimonio_session` e não chama o end session do Authentik.

Cliente OIDC: authorization code com PKCE, scopes `openid profile email groups`, redirect `http://${INTRANET_IP}/patrimonio/api/auth/callback`. Issuer lido de `AUTHENTIK_ISSUER`, default `http://authentik:9000/authentik/application/o/patrimonio/`. No browser o host público é `http://${INTRANET_IP}/authentik/`. O servidor fala com o issuer interno. Os dois valores são variáveis: `AUTHENTIK_ISSUER` e `AUTHENTIK_BROWSER_URL`.
